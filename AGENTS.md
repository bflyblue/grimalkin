# Grimalkin Development Notes

## Project invariants

- Grimalkin is an Odin terminal emulator: native PTY/ConPTY -> `libghostty-vt` state -> Odin display compiler -> buffers/atlases -> one terminal-sized Vulkan quad. Start with `README.md`, `CONTRIBUTING.md`, and `docs/architecture.md`.
- Keep the unstable `libghostty-vt` C ABI isolated in `src/ghostty_shim.{c,h}` / `src/ghostty_vt.odin`. Ghostty owns terminal state and input encoding, not process or PTY lifecycle.
- The renderer is shared across Linux/Windows and macOS (MoltenVK). Preserve the single-quad, integer cell/atlas model unless a task explicitly changes that architecture.

## Cells, shaping, and text advance

- Terminal columns, not font metrics, own horizontal layout. Every independently renderable HarfBuzz cluster starts at its terminal-cell boundary; never carry a HarfBuzz pen or accumulated font advance from an earlier cluster into the next one. Font advances and offsets are only for positioning glyphs inside one cluster or an inseparable ligature group. This prevents hinting or rasterization metrics from causing cumulative drift across a row.
- Preserve terminal column numbers as HarfBuzz cluster values. A wide glyph is represented by a glyph/head cell plus Ghostty spacer cell(s); skip spacer heads/tails when forming the shaping input, but retain the resulting column gap. `shape_run_groups` converts that gap to an integer cell span, and `resolve_shaped_group` rasterizes into exactly `span * cell_width` before slicing the result into ordinary cell-sized atlas tiles.
- Programming ligatures may join several clusters marked unsafe-to-break. Keep their internal HarfBuzz advances, offsets, and negative bearings together inside their shared multi-cell canvas, but anchor the whole group to its first terminal cell. The next group still begins on its own exact cell boundary.
- The atlas stores raster coverage and bearings sliced into cell-sized visuals; it does not define cursor progression. Changes to shaping must retain the advance-isolation, wide-span, and multi-cell-ligature tests in `src/display_compiler_test.odin`.

## Subpixel text rendering

- Grimalkin uses FreeType's Harmony LCD renderer, not the ClearType-style FreeType renderer. FreeType must be built with `FT_CONFIG_OPTION_SUBPIXEL_RENDERING` undefined so `FT_Library_SetLcdGeometry` remains available. Coverage is stored as a linear RGBA subpixel mask and combined component-wise in the text shader; keep it separate from grayscale masks and colour images.
- The safe application default is grayscale with normal hinting. Smoothing is the controlling setting: hinting applies to grayscale and Harmony subpixel rendering, while physical subpixel layout applies only to subpixel rendering. Monochrome always forces FreeType's mono-target hinter. The OSD retains inactive preferences but disables and skips their rows; `application_settings_render_config` must canonicalize inactive inputs so they neither create distinct cache keys nor trigger meaningless resource rebuilds. Packed `FT_PIXEL_MODE_MONO` rows are unpacked to the same R8 mask atlas used by grayscale glyphs. The optional triangular QD-OLED geometry selected for the ASUS PG32UCDMR is red `(-11, 16)`, green `(-11, -16)`, blue `(22, 0)` in FreeType 26.6 coordinates. Keep all active render inputs in `Font_Render_Config`/`Font_Instance_Key` so any effective change rebuilds faces, caches, and atlases instead of reusing stale visuals.
- Subpixel geometry is a property of the physical display, not the font or operating system. Treat the saved RGB/BGR/QD-OLED layout as the panel's native geometry and rotate all three FreeType vectors clockwise by the effective display rotation: `(x,y)`, `(y,-x)`, `(-x,-y)`, or `(-y,x)` for 0°, 90°, 180°, or 270°. Rotation is an active dependency only for subpixel smoothing. `Auto` uses native monitor detection on Windows/macOS; an unknown automatic orientation must canonicalize to grayscale until the user selects a manual angle. Debounce monitor changes and compare effective render configs before rebuilding resources. Grayscale remains the safe default for unknown panels, screenshots, or other cases where physical subpixels cannot be assumed. Per-monitor layout selection and conservative handling of windows spanning incompatible displays remain future work.
- Validate subpixel changes at three levels: packed CPU atlas channels, Vulkan channel blending/zero coverage, and a close-up photograph on the target panel. A plausible on-screen screenshot cannot prove that two-dimensional physical subpixel placement is correct.

## Odin allocator lifetimes

- Treat `context.temp_allocator` as a frame arena. Both normal and benchmark loops call `mem.free_all(context.temp_allocator)` at the beginning of every frame, before event callbacks, terminal draining, display compilation, descriptor construction, or uploads allocate new scratch. Keep that reset in both loops and do not move it to a point where current-frame callback data could already exist.
- Shaping arrays, cluster/group lists, dirty ranges, temporary glyph canvases and tiles, descriptor arrays, upload-region lists, framebuffer readbacks, and short-lived path/C-string conversions may use the temporary allocator only when fully consumed in the same initialization pass or frame. Never retain their strings, slices, pointers, backing storage, or C addresses in `Vulkan_App`, `Text_Demo`, renderer caches, terminal state, callbacks, queued work, or across a Vulkan submission boundary that still reads host memory.
- Persistent CPU state must use a durable allocator and have explicit ownership/destruction. This includes display-grid cells, texture registry pixels and metadata, visual-cache records/maps, font-face objects, copied configuration strings, session state, mapped Vulkan buffers, and anything referenced after the next frame reset. Clone temporary values into durable storage at the ownership boundary rather than relying on the source allocator's lifetime.
- Odin collections inherit an allocator when created. Audit `make`, `append`, cloning helpers, and procedures returning slices or strings: a returned value is not persistent merely because its type has no allocator field. When adding cached or asynchronous data, pass the intended allocator explicitly and add a multi-frame test or memory-growth check that would expose a dangling temporary allocation.

## Regression traps and safeguards

- Shader resource indices vary per fragment. Apply `nonuniformEXT` directly to every `resources[...]` access; qualifying only a temporary can cause the compiler to omit the SPIR-V `NonUniform` decoration from the access itself. Keep mask/tile `texelFetch` and image `textureLod(..., 0.0)` paths separate, consume results inside their branches, and inspect generated SPIR-V after changing this code. See `src/shaders/text.frag`.
- Static demos are insufficient for rendering changes. Test a rapidly updating, style-dense real workload (for example `htop`) plus the deterministic glyph/tile/Kitty demo on hardware Vulkan and llvmpipe where available; enable validation layers and check known blank cells pixel-for-pixel. Do not accept a plausible first diagnosis without isolating CPU snapshot/atlas data, upload behavior, generated SPIR-V, and framebuffer output.
- Kitty virtual Unicode placeholders and direct placements are distinct. The current display compiler renders only virtual placements; do not claim general Kitty image support or treat cursor-reserved blank space from a direct placement as a shaping bug. Follow `src/ghostty_shim.c`, `src/display_compiler.odin`, and their snapshot/display tests.
- Preserve session semantics across platforms: Unix launches the account shell as a login shell rooted at home; Windows uses ConPTY and a deterministic native test child, not interactive PowerShell. App-bundle/resource working directories must not leak into the shell. See `src/session_shim.c` and `src/session_test_child.c`.
- Keep build paths platform-native: Nix + Make on Linux/macOS; CMake/vcpkg via `build-windows.ps1` on Windows. Do not force one platform's compiler/dependency workaround onto another. Run the platform session test, Odin tests, normal build, and package build when relevant.
- Treat user-visible screenshots as required evidence for visual fixes. Preserve unrelated worktree changes and remove diagnostic patches before committing.

## Terminal identity

- Keep `TERM=xterm-256color` and `COLORTERM=truecolor` for broad local and SSH compatibility.
- Later, once Grimalkin's supported escape sequences and terminal capabilities are complete and covered by compatibility tests, create and distribute a dedicated `grimalkin` terminfo entry and change `TERM` accordingly.
- Do not advertise Ghostty or Kitty terminfo: Grimalkin may share features with them, but should only advertise capabilities it implements and tests itself.
