# Grimalkin 0.1.15

Grimalkin 0.1.15 finishes Kitty graphics for images sent over the terminal.
Direct placements now render, PNG transmission is accepted, and images are
layered against text according to the protocol's z-index rules.

## Highlights

- Kitty **direct image placements** now render. They were previously parsed and
  retained but never drawn, so an application that placed an image at the cursor
  got the space reserved for it and nothing in it. Unicode-placeholder
  placements continue to work as before, and still take their own path through
  the display compiler.
- **PNG images** are accepted. Transmissions using `f=100` were rejected before,
  which covered most senders, since PNG is what they generally transmit.
- Images are drawn in the protocol's **three z-index layers**: below the cell
  backgrounds, above them but below the text, and above everything. Text drawn
  over an image, and an image drawn over text, now both behave as specified.
- The **Kitty image storage limit is configurable** through a new
  `kitty_image_storage_mb` setting, and its default rises from 64 MB to 320 MB,
  matching other terminals that implement the protocol. A value of `0` turns
  Kitty graphics off entirely and discards any images already received. The
  setting has no entry in the live settings UI and is documented in the
  [user guide](../user-guide.md).
- Fixed: a placement no longer stays where it was first drawn when the viewport
  scrolls underneath it. Placement geometry is now recollected when the viewport
  moves, which the graphics state alone does not signal.
- Fixed: the terminal was only told its cell size when the window changed grid
  dimensions, which is not the common case at startup. Image geometry therefore
  resolved against a zero pixel size and placed nothing.
- Placement geometry is now resolved by `libghostty-vt` rather than recomputed,
  so omitted source rectangles and grid extents follow the terminal engine
  instead of a second, less complete implementation of the same rules.
- The deterministic Vulkan pixel suite renders offscreen and no longer presents,
  so it needs no display server and runs over SSH and in containers. It
  previously hung indefinitely on hardware GPUs under Wayland.

## Downloads

The release includes:

- a signed, notarized, and stapled Apple Silicon DMG for macOS 14 or newer;
- an x86-64 AppImage plus Debian, Ubuntu, and Arch Linux packages; and
- an x64 installer for Windows 11 24H2 or newer.

Each downloadable artifact is accompanied by a SHA-256 checksum. Linux and
Windows packages require a Vulkan 1.2-capable GPU and current graphics driver;
the Windows package also requires the Visual C++ Redistributable.

## Compatibility and security notes

Grimalkin remains experimental 0.x software and continues to advertise
`TERM=xterm-256color`.

Kitty graphics now covers image transmission, direct and Unicode-placeholder
placements, deletion, queries, and z-index layering. It does not cover animation
or relative placements, which the terminal engine does not implement. Images can
only be transmitted over the terminal itself, not through files or shared
memory. Images placed below the cell backgrounds are not visible, because every
cell background is drawn at full opacity; that is the protocol's defined
behaviour rather than a rendering failure.

`kitty_image_storage_mb` bounds the memory a terminal application can cause
Grimalkin to hold for images. Lower it if a program is expected to send more
image data than a session should retain.

The default OSC 52 policy remains **Write only**. Enabling **Read/write** lets
terminal applications, including applications reached over SSH, query the
local clipboard and should be reserved for trusted sessions.

The Windows installer is not code-signed, so Microsoft SmartScreen may display
a warning. The macOS image is Developer ID signed and notarized by Apple.
