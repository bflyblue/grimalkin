# Grimalkin 0.1.23

Grimalkin 0.1.23 updates libghostty and expands Kitty Graphics Protocol
support, including additional transport, placement, scrolling, and animation
behaviour. It also simplifies several internal settings, OSD, rendering, and
platform paths.

## Expanded Kitty graphics

- Kitty graphics can now be transmitted through regular files and temporary
  files on every platform, as well as POSIX shared memory on Linux and macOS.
- Relative placements resolved by libghostty now render through Grimalkin's
  existing direct-placement path.
- Direct placements follow scroll-region movement and refresh their geometry
  when terminal state changes without recopying unchanged image pixels.
- Transmitted animation frames and explicit frame selections render through
  the existing image-generation cache.
- Unicode placeholders, direct placements, relative placements, scroll-region
  handling, and the supported transport media continue to share libghostty's
  terminal-owned protocol state.

Automatic timed animation playback remains unavailable because libghostty
does not currently expose its internal animation deadline through the public C
API. Explicit animation frame changes are supported. Shared-memory transport
also remains unavailable on Windows because upstream currently implements the
POSIX `shm_open` path only; file and temporary-file transports work there.

## Settings and internal maintenance

- Settings decoding now uses one current disk schema and seeds partial files
  from application defaults.
- Unsupported legacy aliases and unknown fields are no longer migrated.
  Missing or unparsed current options safely retain their defaults.
- OSD setting rows now share one metadata-driven path for presentation,
  enablement, adjustment, reset, and submenu behaviour.
- Fullscreen Vulkan pipelines now pair their handles and layouts with explicit
  ownership, including the padding-glow pipeline's borrowed text layout.
- Unix and Windows session queues share their public read, write, and status
  operations while retaining platform-native synchronization and PTY handling.
- Interactive and benchmark rendering share frame-input sampling, and the
  Ghostty bridge now centralizes result translation.

Together, the maintenance changes remove 342 net lines while preserving the
existing terminal, rendering, and platform boundaries.

## Testing

- The combined 209-test Odin suite, native session checks, and application
  build pass after the changes.
- Kitty snapshot tests cover the expanded transmission, placement, scrolling,
  and frame-selection behaviour.
- The deterministic llvmpipe Vulkan suite and Intel hardware Vulkan validation
  pass for the rendering changes.
- Linux, Apple Silicon macOS, and Windows pull-request builds pass.

## Downloads

The release includes:

- a signed, notarized, and stapled Apple Silicon DMG for macOS 14 or newer;
- an x86-64 AppImage plus Debian, Ubuntu, and Arch Linux packages; and
- an x64 installer for Windows 11 24H2 or newer.

Each downloadable artifact is accompanied by a SHA-256 checksum. Linux and
Windows packages require a Vulkan 1.2-capable GPU and current graphics driver;
the Windows package also requires the Visual C++ Redistributable.

## Compatibility notes

This release intentionally removes migration support for legacy setting names
that were never part of a stable public release. Unrecognized or invalid
options fall back safely to current defaults. Grimalkin remains experimental
0.x software and continues to advertise `TERM=xterm-256color` and
`COLORTERM=truecolor`.

The Windows installer is not code-signed, so Microsoft SmartScreen may display
a warning. The macOS image is Developer ID signed and notarized by Apple.
