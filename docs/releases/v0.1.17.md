# Grimalkin 0.1.17

Grimalkin 0.1.17 fixes three edge cases in the modifier-click link handling
introduced in 0.1.16. Link clicks are now consumed as one complete input event,
the hover cursor follows terminal output correctly, and Unix reports when the
system opener could not be started.

## Fixes

- A link click no longer leaks its synthetic button release into a mouse-aware
  terminal application when opening the browser moves focus away from
  Grimalkin. The press and release are consumed together, while a release
  dropped by the settings overlay or paste confirmation cannot affect the next
  click.
- The pointing-hand cursor now stays synchronized with the dotted link mark
  when terminal output changes the text beneath a stationary pointer. It no
  longer remains over plain text, or fails to appear over a newly arrived link,
  until the pointer moves.
- On Linux and macOS, failure to start `xdg-open` or `open` is now reported
  instead of being mistaken for a successful launch. The detached browser still
  outlives Grimalkin, but a close-on-exec pipe carries launch failures back to
  the terminal without invoking non-async-signal-safe functions after `fork`.
- The Unix launcher also handles applications started with standard input,
  output, or error already closed: its diagnostic pipe is kept clear of file
  descriptors 0 to 2 before the browser process redirects them.

## Maintenance

- Regression coverage now holds the consumed-click lifecycle and failed-opener
  boundary, including the 2048-byte address limit.
- Additional tests lock down terminal cell-size resize decisions,
  `TERM=xterm-256color` and `COLORTERM=truecolor` on Unix, and the lifetime of
  FreeType raster buffers borrowed from a font instance.
- Code comments were audited so they preserve intent, constraints, ownership,
  platform behaviour, and surprising implementation details instead of
  narrating nearby code.
- The optional Nix macOS package once again produces its `.app` bundle; its
  install phase now creates the bundle hierarchy before staging `Info.plist`.

## Downloads

The release includes:

- a signed, notarized, and stapled Apple Silicon DMG for macOS 14 or newer;
- an x86-64 AppImage plus Debian, Ubuntu, and Arch Linux packages; and
- an x64 installer for Windows 11 24H2 or newer.

Each downloadable artifact is accompanied by a SHA-256 checksum. Linux and
Windows packages require a Vulkan 1.2-capable GPU and current graphics driver;
the Windows package also requires the Visual C++ Redistributable.

## Compatibility and security notes

Grimalkin remains experimental 0.x software and continues to advertise
`TERM=xterm-256color`.

Clicking a link still launches a program on behalf of whatever printed the
text. Only `http`, `https`, and `mailto` addresses are recognised, that
allowlist is checked again at the platform-launch boundary, and the address is
passed as one argument rather than through a shell.

The modifier remains fixed per platform: `Command` on macOS and `Alt`
elsewhere. Some Linux window managers claim `Alt`+left-click for moving windows;
where one does, the click never reaches Grimalkin.

The default OSC 52 policy remains **Write only**. Enabling **Read/write** lets
terminal applications, including applications reached over SSH, query the
local clipboard and should be reserved for trusted sessions.

The Windows installer is not code-signed, so Microsoft SmartScreen may display
a warning. The macOS image is Developer ID signed and notarized by Apple.
