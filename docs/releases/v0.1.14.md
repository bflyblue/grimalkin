# Grimalkin 0.1.14

Grimalkin 0.1.14 is a small maintenance release. Its one user-facing change
fixes font fallback on macOS; the remainder tightens internal memory-ownership
rules, records constraints that were previously unwritten, and improves native
build reliability.

## Highlights

- macOS now draws fallback fonts from the system and user font directories
  rather than from a bundled CJK face. Apple's `LastResort` sentinel is excluded
  from matching, so text without a covering font no longer renders as
  `LastResort`'s placeholder glyphs.
- Fontconfig candidates are checked against their actual glyph coverage before
  a face is opened, and zero-width joiners and variation selectors are excluded
  from that coverage test so they cannot make an unrelated font look like a
  match.
- The macOS application bundle no longer ships Noto Sans CJK, making the disk
  image smaller. CJK and other non-Latin text now resolves through the fonts
  macOS already provides.
- Glyph rasterization now names its buffer-lifetime contract in the API itself.
  The rasterizers return a bitmap borrowed from a per-instance conversion
  scratch buffer, are suffixed `_borrowed`, and state the window in which that
  borrow stays valid.
- Allocators are passed explicitly at ownership boundaries instead of being
  redirected through `context`, so no collection silently inherits the frame
  arena from an enclosing procedure.

## Downloads

The release includes:

- a signed, notarized, and stapled Apple Silicon DMG for macOS 14 or newer;
- an x86-64 AppImage plus Debian, Ubuntu, and Arch Linux packages; and
- an x64 installer for Windows 11 24H2 or newer.

Each downloadable artifact is accompanied by a SHA-256 checksum. Linux and
Windows packages require a Vulkan 1.2-capable GPU and current graphics driver;
the Windows package also requires the Visual C++ Redistributable.

## Compatibility and security notes

Grimalkin remains experimental 0.x software and continues to advertise
`TERM=xterm-256color`. Kitty direct image placements are not yet rendered;
virtual Unicode-placeholder placements remain supported.

The default OSC 52 policy remains **Write only**. Enabling **Read/write** lets
terminal applications, including applications reached over SSH, query the
local clipboard and should be reserved for trusted sessions.

The Windows installer is not code-signed, so Microsoft SmartScreen may display
a warning. The macOS image is Developer ID signed and notarized by Apple.
