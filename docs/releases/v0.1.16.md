# Grimalkin 0.1.16

Grimalkin 0.1.16 makes links clickable. Holding a modifier over a URL marks it
and clicking opens it in the system browser, without the address ever reaching
a shell.

## Highlights

- **URLs open on modifier-click.** Hold `Alt` (`Command` on macOS) and move the
  pointer over an address: it is marked with widely spaced dots and the pointer
  becomes a hand. Clicking while the modifier is held opens it in the system
  browser. The click is consumed, so it neither starts a selection nor reaches a
  mouse-aware application such as `nvim` or `htop`.
- Addresses **wrapped across several rows are matched whole**, and a wide
  character next to one bounds it rather than being absorbed into it. Trailing
  sentence punctuation is trimmed, so a URL at the end of a sentence does not
  carry the full stop, while a closing bracket the URL itself opened is kept.
- The mark uses a **new renderer-private underline style**. SGR defines
  underline styles 0 to 5, so the hover style cannot be requested by a terminal
  application, and a hovered link never looks like text an application
  underlined itself. Its dot spacing is measured along the text area and scales
  with the line thickness, so it stays even across cells and keeps its
  proportions on HiDPI displays.

## Downloads

The release includes:

- a signed, notarized, and stapled Apple Silicon DMG for macOS 14 or newer;
- an x86-64 AppImage plus Debian, Ubuntu, and Arch Linux packages; and
- an x64 installer for Windows 11 24H2 or newer.

Each downloadable artifact is accompanied by a SHA-256 checksum. Linux and
Windows packages require a Vulkan 1.2-capable GPU and current graphics driver;
the Windows package also requires the Visual C++ Redistributable.

## Compatibility and security notes

Grimalkin remains experimental 0.x software and continues to advertise
`TERM=xterm-256color`.

Clicking a link launches a program on behalf of whatever printed the text, so
the boundary is deliberately narrow. Only `http`, `https`, and `mailto`
addresses are recognised, and that allowlist is enforced again where the link is
opened rather than trusting the detector, so a future change to detection cannot
silently widen what a click can run. The address is passed as a single argument
to the platform opener — `xdg-open`, `open`, or `ShellExecute` — and never
through a shell, so shell metacharacters in an address are inert.

Addresses are found by their scheme. A bare `example.com` or `www.example.com`
is not a link: inferring one is a source of false positives pointed at a program
launcher. Detection reads the visible viewport, so a URL whose scheme has
scrolled above the top of the window does not match until it is scrolled back
into view; no match is preferred to opening a truncated address.

The modifier is fixed per platform and has no setting yet. Several Linux window
managers claim `Alt`+left-click for moving windows; where one does, the click
never reaches Grimalkin, and the binding to change is the window manager's.

The default OSC 52 policy remains **Write only**. Enabling **Read/write** lets
terminal applications, including applications reached over SSH, query the
local clipboard and should be reserved for trusted sessions.

The Windows installer is not code-signed, so Microsoft SmartScreen may display
a warning. The macOS image is Developer ID signed and notarized by Apple.
